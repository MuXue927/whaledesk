# 1. 项目目标与非目标

## 1.1 目标

把 DSH（DeepSeek Harness）里那只"小鲸娘"请到 Windows 桌面上，做成一个**常驻、可交互、有实用性**的桌面伴侣：

1. **与 DSH 联动**：显示当前会话阶段/气泡、长任务计时与完成提醒；能唤起/隐藏 DSH 窗口；能对她摸头、喂食。
2. **系统监控**：CPU/内存/GPU/显存/磁盘/网络实时面板；内存和磁盘分级预警；结束"内存大户"（进程家族）。
3. **磁盘清理**：C 盘白名单清理（二次确认 + 回收站）；"最占空间目录"分析——解释**里面是什么、哪些能删、哪些不能删**。
4. **效率工具**：拖放（把文件/路径交给 DSH 或复制到指定目录）、快捷启动、剪贴板历史、久坐提醒、番茄钟、下载完成提醒。
5. **可交付**：一键打包 + 一键安装/升级/回滚，版本可查。

## 1.2 非目标（明确不做）

- **不接管 DSH 窗口**：只做"唤起 / 隐藏 / 置前"，不注入、不 hook、不改 DSH 代码。
- **不写 DSH 或插件的数据**：只读它们的 HTTP 接口与公开数据文件。
- **不做管理员操作**：不提权删除、不点 UAC、不改系统设置、不删系统/个人文件。
- **不收集数据**：剪贴板历史、保留/忽略清单只存本机；不上传、不联网（除访问本机 DSH）。
- **不做"万能清理"**：清理范围是白名单；分析给结论但不替用户做危险决定。

# 2. 技术选型

| 维度 | 选择 | 理由 |
|---|---|---|
| 语言 | **C# 13 / .NET 9** | Windows 桌面（WPF）一等公民；P/Invoke、PDH、COM、剪贴板都成熟；单文件发布与自检方便 |
| UI | **WPF**（`net9.0-windows`） | 需要逐像素透明、Alpha 命中测试、无边框分层窗口；WPF 的 `AllowsTransparency` + `WS_EX_LAYERED` 最省事 |
| 进程形态 | **独立 exe 进程** | DSH 的宿主跑在 Electron `utilityProcess` 里，**插件无法创建桌面窗口**，只能走独立进程 |
| 与 DSH 通信 | **本机回环 HTTP**（`127.0.0.1`，端口可能是动态的：历史默认 19387，实测 64688） | 唯一稳定、无需鉴权（`/api/pet/*`）的公开通道；端口由 `DshEndpointDiscovery` 自动发现 |
| 系统数据 | **PDH 性能计数器** + WMI/`GetSystemTimes`/`GetProcessIoCounters` | CPU/GPU/磁盘/IO 速率的官方来源 |
| 第三方依赖 | **零 NuGet 依赖**（仅 BCL + WPF + `Microsoft.VisualBasic.FileIO` 用于回收站删除） | 离线可构建、发布体积小、无可信链风险 |
| 脚本 | **Windows 批处理 + PowerShell** | 安装器/快捷方式/打包；批处理必须**纯 ASCII**（见 §11 编码问题） |
| 构建 | `dotnet build/publish`（框架依赖发布） | 框架依赖发布约 6 MB；自包含发布约 150 MB（首次构建需联网下载 win-x64 runtime pack） |

**为什么不是 DSH 插件**：这是本项目第一个、也是最关键的技术判断。DSH 渲染进程里的插件无法创建独立窗口；即使创建也会随 DSH 退出。独立进程还能在 DSH 崩溃/升级时继续存活。

**UI 容器三种形态（重要设计）**：

| 形态 | 用在 | 为什么 |
|---|---|---|
| **同一窗口内的"卡片"** | 监控面板、清理面板 | 需要贴着宠物、随她移动；高度受严格约束 |

# 5. 关键设计决策与取舍

### D1 · 独立进程而非插件（已定）
插件无法创建桌面窗口且随 DSH 退出。代价：需要进程间通信（回环 HTTP），好处：DSH 崩溃/升级时宠物仍活着。

### D2 · 安装到 `%LOCALAPPDATA%` 并清完整性标签（血泪教训）
DSH 会给工作区目录打上 **Low 完整性标签**（`Mandatory Label\Low ... (OI)(CI)(NW)` + `Everyone:(CI)(DENY)(DC)`）。从低完整性 exe 启动的子进程同样是 Low → 无法创建正常子进程 → DSH 启动即 `0x80000003 (STATUS_BREAKPOINT)`、`explorer.exe` 崩 `0xc0000142`。
**决策**：把 exe 复制到工作区外的 `%LOCALAPPDATA%\WhaleDesk`，用 `icacls /setintegritylevel Medium` 修正 → 一切正常。安装器固定执行这一步。

### D3 · 拖放"零副作用"，但最终同时写文件与文本（需求修正）
最初只复制**路径文本**（认为最安全）。用户实测：在资源管理器里粘贴是**灰的**——因为没写 `FileDrop`。
**修正**：同时写 `FileDrop`（真实文件列表 → Explorer 可粘贴文件）+ `UnicodeText/Text`（路径文本 → 编辑器/DSH 可粘路径），并且**写后读回校验**（文件列表逐项 + 文本）。

### D4 · 卡片高度必须用"内容期望高度"
卡片内容会**异步变高**（目录扫描完成后才填行）。用 `ActualHeight` 重测会被**当前过矮的窗口反向压缩**，量出来还是旧值 → 窗口不够高 → 宠物被裁。
**决策**：`MonitorPanel.DesiredHeight => ScrollViewer.ExtentHeight + 6`（内容自身尺寸，与视口无关）；限高公式 `min(工作区×52%, 工作区−宠物基准高度−70)`；卡片放进**限高滚动容器**。

### D5 · 菜单必须有自己的窗口（三次演进）
1. 画在宠物窗口里 → 项一多就把宠物顶出屏幕；
2. 独立窗口钉在屏幕右下角 → 离宠物太远，且 `Deactivated→Close()` 让鼠标一移过去就消失；
3. **当前**：独立窗口、**贴宠物弹出**（右边放不下就放左边）、**右侧二级 flyout**、`PopupDismiss`（点外面才关）。
另有 `EnforcePetVisible()` 兜底：任何布局变更后若宠物越界，自动挪回并记 WARN。

### D6 · 清理默认"进回收站 + 删除前重校验"
空间分析的结论可能过期。删除每条前重新执行：① 存在且非重解析点 ② 重新分类必须仍是 SafeCache ③ 位于 `%LOCALAPPDATA%`/`%APPDATA%`/`%TEMP%` ④ 走回收站（可还原）。被拒绝的逐条记录。

### D7 · "是否常用/想保留"不靠名单，靠证据 + 显式标记
- **证据**（自动）：运行中进程的可执行路径包含目录名（`AppData\Local\Google` ← `...\Google\Chrome\chrome.exe`）；或目录两层内 14 天内有写入。
- **显式**（手动）：分析窗口 ★ = 加入保留清单（永久不再建议动）；右键 = 忽略（不再出现）。
- 判定优先级：保留 → 系统 → 个人 → 缓存/日志/旧版 → **在用** → 应用数据（建议卸载）→ 不确定。

### D8 · 内容分析按"归属 + 能否重建"分类，不识别具体软件
白名单永远补不全。四个问题就够：这是缓存/日志/旧版？是已装程序？是 Windows？是你的文件？——再叠加**上下文**（同一名字在 AppData 下=应用数据，在 Documents 下=你的文件）与**逐层下钻**。

### D9 · 三层验证：自检 / 演练 / 探针
纯逻辑必须能在无 UI 环境断言（126 项）；清理只读演练 33 项；UI/集成用 `--probe-*` 无头跑并记日志。**无法自动化的**（真实拖拽、原生对话框、悬停展开）明确列为人工项。

### D10 · 后台进程不能抢焦点 → 用"最小化+恢复"轻推
`SetForegroundWindow` 从后台进程通常失败；`Win32.Activate` 用 `ShowWindow(SW_MINIMIZE)` + 60ms + `SW_RESTORE` + `SetForegroundWindow` 尽力而为，失败也如实记录（`visible-but-not-foreground`）。

## 8.3 升级兼容策略

1. **只用免登录端点做核心功能**；有鉴权的端点只在安装期用，失败不影响桌面运行。
2. **`--probe-dsh-api`**：逐端点打印 `OK / AUTH / MISSING / DOWN` + 字节数 + 对应功能 → DSH 升级后跑一次即知哪坏了（真机输出示例：state OK 1073B、pets OK 7038B、plugin-manager AUTH、skin-center AUTH、ledger exists=True）。
3. **容忍缺字段**：JSON 缺字段退化为默认值，不抛异常；轮询失败自动降速、恢复自动回速。
4. **账本走磁盘文件**，不依赖 HTTP。
5. **做不到**：DSH 若大改返回结构或账本格式，需要改代码适配（无法自动适配任意变更）；拿不到 DSH 版本号，只能探测能力（端点是否可用）。

# 12. 已知限制与未实现

**限制（承认，不打算隐藏）**
1. 无法拦截 Explorer 的"同名文件"对话框；只能提供替代路径（自动改名复制）。
2. 空间分析"在用"是启发式（进程路径/近期写入），可能误判 → 可 ★ / 右键纠正。
3. 剪贴板历史在"某程序长时间占用剪贴板"时可能漏记；文本 60 条 + 图片 10 张（<24×24 忽略）。
4. DSH 无版本接口，只能按能力探测；DSH/插件大改接口或账本格式时需改代码适配（自动更新检查已实现，被动式）。
5. 后台进程抢焦点只能"尽力而为"（最小化+恢复），失败如实记录。
6. 框架依赖版需目标机装 .NET 9 桌面运行时；自包含版无此要求，但首次构建需联网下载 runtime pack。
7. 真实鼠标拖拽、原生对话框、悬停展开等只能人工验。
8. **平台限制：仅支持 Windows 10/11 x64**；macOS/Linux 无法运行（UI 依赖 WPF/Win32），需重写 UI 与服务层（见 README「平台支持」）。

**技术债**
- `PetMenu.cs`（旧内嵌菜单）已于 0.20.0 删除；
- `PetWindow.cs` 3001 行偏大，可按"布局/交互/提醒/接线"拆分；
- 部分探针为历史遗留，可合并。

```
我：改代码 → whaledesk\scripts\build-dist.cmd
       （dotnet publish --no-restore → dist\app\ + assets\ + 图标 + VERSION.txt + 复制 install.cmd/make-shortcut.ps1）

       ① 退出旧版（--quit，最多等 10s，超时 taskkill）

       ③ xcopy dist\app\* → %LOCALAPPDATA%\WhaleDesk
       ④ icacls 清完整性标签（Medium）
```

## 15.4 术语

- **DSH**：DeepSeek Harness 桌面应用（Electron）。
- **完整性级别（IL）**：Windows 强制完整性控制；Low 进程受限，无法创建正常子进程。
- **家族聚合**：把同名多进程（如 Chrome 的 30 个）视为一个应用。
- **上膛（arm）**：危险操作的一次确认态，需在时限内二次点击才执行。
- **SafeCache / InUse / Kept / Personal / System**：空间分析的结论等级（可删 / 在用·保留 / 已标记保留 / 你的文件 / 系统）。
- **探针（probe）**：无头环境下走真实代码路径并记录日志的验证模式。

## 二十一、签名、"未知发布者"与 GitHub 发布（v0.21.0）

### 为什么 Windows 会提示"未知发布者 / 没有有效的数字签名"
两个独立原因叠加：
1. **文件带 Mark-of-the-Web (MOTW)**：是否带取决于浏览器/下载器/解压工具——**GitHub Release 下载的 zip 在部分环境里不带标记，解压后双击 `install.cmd` 不会弹任何提示**（实测）；带标记时才会弹「打开文件 - 安全警告」。
2. **exe/cmd 没有代码签名证书**：SmartScreen 认为发布者未知。

### 处理方案（按代价排序）
| 方案 | 效果 | 成本 |
|---|---|---|
| 右键 → 属性 → **常规页最下方**勾选「解除锁定」（仅带 MOTW 时出现）；或 `scripts\unblock-files.ps1` 批量解除 | 消除 MOTW 引起的"打开文件-安全警告" | 免费 |
| 自签名证书 + 导入「受信任的根证书颁发机构」+ `scripts\sign-self.cmd` | 只对本机有效 | 免费 |
| 购买代码签名证书（OV/EV），`signtool sign` 签 exe 和 cmd | 所有用户都不再提示 | 约 $100–400/年 |
| 上架 Microsoft Store | 不提示 | 需开发者账号 |

**诚实说明**：没有 CA 证书时，无法让**其他用户**的 Windows 不提示；本项目只能提供解除锁定与自签名脚本。

### GitHub 发布
1. 在 GitHub 建仓库（默认约定 `MuXue927/whaledesk`，与自动更新检查的 `UpdateChecker.DefaultRepo` 一致）
2. 创建 fine-grained token（权限：Contents = Read and write）
3. 运行：
   ```powershell
   powershell -ExecutionPolicy Bypass -File whaledesk\scripts\publish-github.ps1 -Repo MuXue927/whaledesk
   ```
   脚本会：建仓库（已存在则跳过）→ `git init/add/commit` → push `main` → 创建 `v<version>` Release 并上传 `WhaleDesk-<version>.zip`。token 只在内存中使用，不落盘。
4. 若仓库名不同：改 `UpdateChecker.DefaultRepo`（`UpdateChecker.cs`）后重新打包，否则自动更新会查错仓库。

### 自动更新检查行为
- 启动时异步检查一次，之后每 24 小时一次（`UiState.AutoUpdateCheck`，默认开）
- 发现新版本：气泡提示「有新版本 vX」，菜单「新手与帮助 → 检查更新」显示「（发现 vX）」
- 用户点菜单项：立即检查，若有新版则**打开 Release 页面**（不静默下载/安装）
- 无网络/被拦：日志 `update check failed: ...`，不打扰用户
- 自检：`update-version-compare`（v 前缀/预发布/乱码标签）
- 探针：`WhaleDesk.exe --live --seconds 10 --probe-update`
